# DAY18 후속 연락 계약 — 2026-09-04 21:00

## 구현 전 계약

원문 SCENE17의 “내일 연락할게. 네가 이야기할 수 있는 시간도 물어볼게.”는 주인공의 연락 약속이지, 하은이 내일 통화 시간을 수락한 사건이 아니다. SCENE18의 계속 만나고 싶다는 말/확신 유보/거짓말 정정 역시 통화 예약이 아니다.

현재 `followUpContact`는 여러 의미를 합친 기존 저장 필드다. `/1`의 초기 facts나 reducer를 바꾸면 선택 재생과 JSON 동등성 검증이 깨진다. 이번 변경은 유효한 기존 chapter에서 읽기 전용 후속 연락 계약을 도출하고, 새로 완료하는 Story History에 별도로 기록한다. 기존 chapter·완료 이력은 수정하지 않는다.

입력: 검증된 DAY18 chapter, 실제 선택 ID와 연락 허용 상태.

출력: `status` (NONE / CONTACT_PROMISED / DISCUSSION_PENDING), `promisedBy`, `contactDay`, `agreedTime`, `sourceChoiceId`. `contactDay:19`는 주인공이 연락하기로 한 날일 뿐 예약일이 아니다. 현재 구현된 모든 경로에서 `agreedTime:null`이다. contact 불가/미선택은 NONE, night_defer는 CONTACT_PROMISED, night_correct/future_continue/future_unsure는 DISCUSSION_PENDING이다.

흐름: 기존 선택 → 기존 reducer 그대로 → 읽기 전용 계약 계산 → 최종 완료 cue에서 새 History에 보관. DAY19는 레거시 boolean을 통화 동의로 사용하지 않고 이 계약을 사용해야 한다. 과거 완료 저장은 필요할 때 chapter에서 계산하며 자동 이력 보정하지 않는다.

범위 제외: 하은의 당일 통화 불가 및 시간 제안/수락 분기는 아직 없다. 이를 임의 감정 점수나 무작위로 결정하지 않는다. 다음 단계에서 출처가 있는 입력과 버전별 재생을 먼저 설계한다. 이번 작업을 불가 분기 구현 완료로 표시하지 않는다.

검증 계획: 약속/미합의/연락 종료/무연락 반례, 원본 JSON 불변, 손상 저장 거부, 실제 SaveManager 이력 보존, 완료 중복 방지. UI와 대사는 변경하지 않으며 실제 브라우저 플레이 검증을 대신하지 않는다.

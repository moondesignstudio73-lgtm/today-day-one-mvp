# DAY 15 V4 구현 격차·콘텐츠 커버리지 감사

권위·분기 계약: `docs/day15/DAY15_NOTION_SOURCE_LOCK_V4.md`

상태: `AUDIT PASS · REBUILD REQUIRED`

이 감사는 전체 대본을 대신하지 않는다. 구현자는 작업 직전 소스 잠금에 기록된 Notion 하위 페이지 본문을 다시 완전 조회하고 그 본문으로 장면·대사·선택 데이터를 작성해야 한다.

## 결론

현재 DAY 15 신규 시작 런타임은 Notion V4와 직접 대응하는 장면이 `0/24`다. 기존 V1은 8장면·3선택의 책방/작은 전시/강변/카페 여가 데이트와 예약 라벨 불일치를 다루며, 최신 원고의 조건부 한강 갤러리 참석, 시우와의 비교, 완전한 자기 오후, 관계 갈등, 현재 감상 전달을 구현하지 않는다. 신규 진행은 V4로 교체하고 기존 `m30-day15-current-leisure-date` 세션과 `day15CurrentLeisureDate*` 필드는 이미 진입·완료한 저장의 복원 전용으로 유지한다.

## 최근 3 DAY 반복 방지

- DAY 12의 직장 협업과 윤서진 거리, DAY 13의 공원 사진·아라 첫 만남, DAY 14의 꽃·나리·위로 거절을 반복하지 않는다.

- 갤러리와 카페는 장소 수를 채우기 위한 방문이 아니다. 전시는 비교와 자기 감상을, 카페는 질투·불안·통제의 실제 관계 결과를 담당한다.
- 소비·경제 설명은 의상·카페 주문의 생활 동작에만 제한하고 본문 20% 아래로 유지한다.

## V4 상태·호환 전략

- 신규 필드는 다음 계약에서 타입·기본값·enum·체크포인트를 확정할 `day15V4*` 네임스페이스로 분리한다. 기존 `day15ActivityStrategy`, `day15ChangeStrategy`, `day15PrivacyStrategy`에서 V4 선택을 추정하지 않는다.
- 신규 시작 선택기는 DAY 14 V4 완료 뒤 `day14V4ExhibitionInvitation`을 읽어 참석 가능성과 자기 오후를 구분한다. V1 진행 중·완료 저장은 기존 런타임으로 복원한다.
- `DIRECTLY_OBSERVED`, `TOLD_BY_HAEUN`, `UNKNOWN` 지식 출처는 단일 시우 필드가 아니라 이름, 외모, 역할, 전문 행동, 작품 정보, 현장 대화별 장부로 보존한다. 불참·무연락 저장에서 시우와 작품 현장 지식을 생성하지 않는다.
- DAY 12 윤서진 제안과 DAY 13 아라 관계는 실제 필드 조합으로 판정한다. `seojinAffection`과 `seojinStatusInterest`는 서로 대체하거나 합산하지 않는다.
- 질투 표현, 불안 인정, 통제 요구, 통제 지속, 하은 이탈, 경계 해결을 한 개의 관계 점수로 축약하지 않는다.
- 어깨 접촉은 자격과 실제 발생을 별도 저장한다. 전시 자료 제안·수락·읽기도 각각 독립 상태로 남긴다.
- 불참/무연락 경로도 자기 행동과 마감 선택을 완료하고 정상적으로 DAY 16 잠정 훅에 도달해야 한다.

다음 계약에서 최소한 `scenarioVersion`, `sceneCheckpoint`, `choiceIndex`, `selectedChoiceIds`, `galleryInvitation`, `attendanceRoute`, `ownAfternoonRoute`, 사실별 `knowledgeLedger`, `viewingStrategy`, `restDecision`, `cafeRoute`, `conflictStrategy`, `controlContinued`, `haeunLeft`, `day14CallbackRoute`, `seojinDisclosure`, `araDisclosure`, `boundaryResolved`, `shoulderContactEligible`, `shoulderContactOccurred`, `publicMaterialOffered`, `publicMaterialAccepted`, `publicMaterialRead`, `jihoonMessagePending`, `completed`의 타입·기본값·enum·nullable 여부와 허용 전이를 고정한다.

코드화 전에 V1/V4 라우팅 진리표도 확정한다. V1 선택/체크포인트/완료 흔적이 있는 저장, V4 버전 저장, DAY 15 미진입 저장, 버전 없는 저장, 서로 모순된 저장을 각각 분리하고 추정 변환하지 않는다. `choiceIndex`, `sceneCheckpoint`, `selectedChoiceIds`가 어긋난 경우의 복원 권위와 복구 실패 처리도 같은 계약에서 정한다.

허용 전이는 최소한 `shoulderContactOccurred → shoulderContactEligible`, `publicMaterialRead → publicMaterialAccepted → publicMaterialOffered`, `haeunLeft → shoulderContactOccurred=false`, `NO_CONTACT → 직접 관찰 지식 없음`, `controlContinued → boundaryResolved=false`를 만족해야 한다. 자격처럼 계산 가능한 값은 저장할지 복원 시 계산할지 계약에서 한 방식으로 통일한다.

## 이미지·연출 선행 감사 항목

- 현재 V1의 반복 배경과 하은 스탠딩 스프라이트만으로 V4의 핵심 행동을 DAY 2 기준으로 충족했다고 보지 않는다.
- 에셋 감사는 초대 휴대전화, 갤러리 세 사람 소개, 작품 앞 시선, 시우의 좌우 실수, 카페 갈등, 공개 자료 건네기, 조건부 귀가 어깨 접촉, 자기 오후 독서/무연락 마감을 장면 단위로 검토한다.
- 신규 제작 수량은 기존 자산 원본 육안 검사 뒤 확정한다. 필요한 비트맵 생성·편집은 Codex 내장 ImageGen과 결정적 로컬 후처리만 사용하며 API SDK·외부 API·`OPENAI_API_KEY` 경로는 사용하지 않는다.
- 모든 후보는 16:9, 원본 비율, 얼굴·손·핵심 소품, 하은 정체성, 조명·원근, 데스크톱/모바일 UI 안전영역을 DAY 2 기준과 비교한다.

## 10문항 예비 검수

| 항목 | 예비 판정 | 근거/남은 관문 |
|---|---|---|
| 연애 중심 | EXPECTED PASS | 비교 감정과 현재 감상 전달이 중심이다. 구현 뒤 전체 대사 비중으로 재검수한다. |
| 실제 관계 변화 | EXPECTED PASS | 통제 지속 시 이탈, 해결 시 거리 회복이 다르다. 저장 복원 경로로 재검수한다. |
| 조건부 대사 | EXPECTED PASS | 참석·불참·통화·무연락·선행 콜백별 대표 경로로 재검수한다. |
| 최근 경험 반복 방지 | EXPECTED PASS | 직장·공원 사진·꽃 거절과 다른 전시/사회관계 경험이다. 장면 역할표로 재검수한다. |
| 시스템 설명 20% 이하 | EXPECTED PASS | 구현 뒤 대사·내레이션 전체 행을 분모로 시스템 설명 행 비율을 계산한다. |
| 하은 주체성 | EXPECTED PASS | 혼자 관람, 갈등 중단, 거리, 자료 공유를 하은이 결정하는지 전 경로로 확인한다. |
| 새 인간관계 필요성 | EXPECTED PASS | 시우가 경쟁 대상이 아니라 하은의 독립된 현재 관계를 드러내는지 대사 QA한다. |
| 설렘 | EXPECTED PASS | 현재 감상 공유와 조건부 접촉 또는 존중하는 거리 마감을 대표 경로에서 확인한다. |
| 기억상실 미스터리 진전 | CONDITIONAL PASS | `지난번`의 사회적 기억 격차를 직접 겪지만 새 사고 단서는 없다. 별도 폭로를 추가하지 않고 챕터 계약의 지식 장부로 범위를 고정해야 한다. |
| 다음 훅 | EXPECTED PASS | 지훈의 잠정 메시지만 남고 만남을 확정하지 않는지 모든 완료 경로로 확인한다. |

아직 구현 전이므로 `EXPECTED PASS`는 완료 판정이 아니다. `CONDITIONAL PASS`는 구현 전에 챕터 계약으로 명시하고, 최종 10문항에서 3개 이상 실패하면 DAY 15를 완료 처리하지 않는다.

# 손 화풍 재신고: 실행 경계 보강

## 확인 사실

사용자 첨부에는 실사형 전경 손이 있지만 현재 로컬 `yuri-menu-wait-water-v9.png`에는 전경 손이 없다. 두 이미지를 직접 확인했다. 이번 작업에서 이미지를 재생성하거나 기존 수정본 제작을 새 작업으로 계산하지 않았다. imagegen 스킬의 기존 출력 우선 검토와 불변 요소 보존 원칙에 따라 이미 손이 제거된 수정본을 재사용했다.

실제 사용자 탭의 URL·응답을 확보하지 않았으므로 원인을 캐시로 확정하지 않는다. 확인된 개선 지점은 CG 공통 렌더러가 `step.source`를 그대로 사용한다는 점이다. 구버전 단계가 들어오는 경우에도 승인본으로 전환하도록 `story-cg-asset-policy.mjs`를 추가했다. 프리로드와 표시 시점에 같은 정책을 적용하고 검수 리비전 쿼리로 캐시 키를 갱신한다. 저장 파일은 수정하지 않는다. 최상위 스크립트는 v279다.

## 회귀 검증

손 이미지 경계 보강 직후 전체 Node 테스트 852/852 PASS, `node --check game.js`와 `git diff --check` PASS다. 후속 DAY28 작업에서 최상위 캐시는 v280으로 증가했으며 이미지 정책은 그대로 유지한다.

- 모든 등록 구버전/승인본 URL에 대해 승인 파일로 정규화하고 새 캐시 키를 사용하는지 검사한다.
- 상대 URL, 쿼리 포함 URL, 동일 사이트 절대 URL, 하위 경로 호스팅, 반복 정규화, 외부/무관 URL 보존을 검사한다.
- 기존 배포 파일과 승인 파일의 바이트 동일성을 검사한다.
- CG 표시 경계 연결과 기존 CG 타이머·스킵 수명주기를 함께 검사한다.
- 수정 지침: `STORY_V4_IMAGE_STYLE_RULES.md`의 ‘재신고 시 실행 경계 규칙’ 참조.

새 코드가 아직 로드되지 않은 열린 탭이나 서버가 구버전 배포 자체를 제공하는 상황까지 이 변경이 소급 수정하지는 않는다. 실제 사용자 화면 해결 판정에는 사용 중인 배포 URL과 새 코드 로드 확인이 필요하다.

## 2026-09-07 재신고 원인 확정과 배포 경계 수정

- 사용자 첨부 화면은 전경 POV 손이 남은 DAY18 유리 식사 장면이다. 현재 로컬 승인본 `yuri-menu-wait-water-v9.png`는 전경 손·손목·소매가 0개이므로 새 이미지를 다시 생성하지 않고 제거본을 유지한다.

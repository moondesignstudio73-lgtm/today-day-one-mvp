# DAY 1 VISUAL / UI / ASSET QA COMPLETE

검사일: 2026-08-26

## 1. 발견된 문제

- 대사마다 하은 전신 포즈가 저해상도 상반신 표정 이미지로 교체되어 화면을 과도하게 점유했다.
- 첫 등장 전 천장 독백에서 하은 초기화 이미지가 미리 노출됐다.
- 캐릭터별 위치·깊이·화자 포커스·공통 바닥선이 런타임에 연결되지 않았다.
- 이미지 선로딩이 없어 첫 표시 시 깜빡임 위험이 있었다.
- 대화창 높이가 고해상도에서 화면의 약 10%까지 작아졌다.
- 의료진 6종은 503–512px 높이로 최대 표시 크기의 1.5배 원본 기준을 충족하지 못했다.

## 2. 수정한 코드

- `src/day1-campaign-runtime.mjs`: 화자별 `focusCharacterId`, 캐릭터 `stage` 데이터 추가.
- `game.js`: DAY 1 포즈 유지, 첫 등장 전 숨김, 공통 스테이징·포커스 적용, 자산 선로딩, 종료 정리 추가.
- `styles.css`: 공통 바닥선, position/depth 프리셋, active/sub 포커스, 전환, 검사 광원, 반응형 대화창 추가.

## 3. 이미지 검사 결과

- A: 병원 배경 2종, 승인 CG 3종, 하은 전신 포즈 9종.
- B: 없음.
- C: 담당 의사 3종, 간호사 3종. 자세한 내용은 루트의 `IMAGE_REGENERATION_REQUIRED.md` 참조.
- D: 없음.

## 4. 재생성 필요한 이미지

의료진 6종. 기존 파일은 런타임 호환을 위해 임시 유지한다.

## 5. 새롭게 만든 이미지 생성 프롬프트

`IMAGE_REGENERATION_REQUIRED.md`에 공통·캐릭터별 프롬프트를 기록했다. 내장 생성 시도 1회는 투명 alpha 실패로 채택하지 않았다.

## 6. 캐릭터 스테이징 개선

`left`, `center`, `right`, `backgroundRight`, `foregroundRight` 위치와 `foreground`, `normal`, `background` 깊이를 데이터 속성으로 통일했다. 모든 캐릭터는 대화창 위 동일 바닥선에 정렬되며 화자만 1.025배/opacity 1, 비화자는 0.975배/opacity .84로 완만하게 전환된다.

## 7. UI 개선

대화창은 `clamp(138px, 18dvh, 280px)`로 조정해 1366×768부터 2560×1440까지 약 18–20%를 유지한다. 기존 이름표·내레이션 구분·키보드 선택 UI는 보존했다.

## 8. Scene 전환 개선

DAY 1 전체 sequence의 배경·스프라이트·CG를 시작 시 선로딩한다. 첫 하은 포즈 큐 전에는 캐릭터를 숨기고, 포즈는 명시적 `characterEnter`에서만 바뀐다.

## 9. 실제 DAY 1 플레이 테스트 결과

- 9개 선택 경로, 중간 저장 복원, CG·오디오·입력 잠금 테스트 PASS.
- 실제 브라우저에서 첫 등장 전 숨김, 하은 포즈 유지, 의료진 3인 공통 바닥선, 의사 화자 포커스 PASS.
- 1920×1080, 2560×1440, 1366×768에서 가로 오버플로 없음.

## 10. 아직 남아 있는 문제

의료진 6종의 고해상도 RGBA 원본 교체가 남아 있다. 투명 배경 생성 실패본은 프로젝트에 넣지 않았다.

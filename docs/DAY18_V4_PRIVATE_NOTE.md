# DAY18 개인 메모 — 구현 계획

SCENE20 `alone_note`를 선택하면 일반 독백보다 먼저 휴대전화의 개인 메모를 읽는다. 자신의 마지막 실제 발언만 적으며 상대의 표정이나 마음을 추측하지 않는다. 보내기 기능/수신자/새 메시지 이력은 없다.

입력: 유효한 기존 chapter와 선택 직전 반응의 주인공 발언. 출력: `privateNote` 런타임 이벤트. 메모 내용은 매번 결정적으로 파생하며 facts·저장 스키마를 변경하지 않는다. 해당 반응에 발언이 없으면 빈 메모임을 표시하고 사건을 발명하지 않는다.

그래프: 혼자 마무리 선택 → 개인 메모(클릭으로 읽기 완료) → 보내지 않았다는 독백 → 여행 사진. 다른 선택에는 메모가 없다. 재개 시 같은 선택 반응을 다시 표시한다.

## 화면 계획 / frontend-design 적용

- 색: 기존 방 #17182b, 메모 종이색 #f6f8fc, 글자 #263347, 구분선 #ccd4df, 강조 #596f93. 새 테마가 아니라 게임 속 메모 도구다.
- 글꼴: 기존 게임 한글 글꼴 상속. 제목 18px/본문 18px, 1.8 행간. 왼쪽 정렬, 최대 36자 안팎의 짧은 줄.
- 배치: 방 위 작은 세로 메모, `내 메모 / 나에게만` → 내가 한 말 → `읽고 닫기`. 대화 패널은 이 동안 숨기고 클릭/키보드 진행 입력을 그대로 사용한다.
- 초기 구상의 대화창 색상 변경만으로는 문자와 혼동되므로 독립된 문서 패널로 수정했다. 발신자 말풍선/전송 버튼/점수 장식은 쓰지 않는다. 줄바꿈과 작은 화면 스크롤을 허용한다.

자동 검증과 실제 표시/닫기/저장 재개를 따로 기록한다. 컵 씻기 및 손 동작은 별도 미완료이며 DAY18은 PARTIAL이다.

## 실행 결과

- 마지막 선택 반응에서 실제 주인공 대사만 추출해 별도 `privateNote` 패널에 표시한다. 주인공 대사가 없는 무연락 경로는 빈 메모다. 신규 송신/수신/동의 이력이나 점수 변화 없음.
- 패널은 현재 Story 입력을 기다리고 Enter/클릭으로 닫힌다. 다음 이벤트 시작 시 제거되며 일반 대화가 다시 보인다. HTML 이스케이프 적용. 메모 렌더러는 대사 타자/LOG 함수를 호출하지 않는다.
- 실제 game194 / styles99: 유리 미고지 → 내일 시간 질문 → “알겠어. 오늘은 쉬어.” → 메모 선택. 해당 문장이 개인 메모에 표시되고 문자/일반 대화는 동시에 노출되지 않음을 확인했다. 방/22:00 유지.
- 메모 열린 상태에서 새로고침/이어하기 → 같은 메모 재생. Enter로 닫기 → 보내지 않았다는 원문 독백 복귀. 콘솔 오류/경고 없음, 기존 사용자 저장 복원 완료.
- frontend-design 스킬의 별도 문서 패널/왼쪽 정렬/절제된 색상 계획을 적용했고 실제 화면을 시각 검토했다. 모바일 실측은 NOT RUN이며 최종 UI 게이트에 남긴다.
- 전체 테스트 450 PASS / 0 FAIL, 구문·diff 검사 통과. 최초 회귀 실패는 기존 styles98 캐시 기대값이었으며 styles99로 갱신 후 재실행했다.

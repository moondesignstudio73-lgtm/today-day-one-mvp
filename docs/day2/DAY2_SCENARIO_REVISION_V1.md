## 2. Voice Profile

### 주인공

- 문장: 짧고 구체적. 관찰 뒤 확인 질문을 붙인다.
- 호칭: 하은에게 반말, 의료진에게 존댓말. 이름은 필요할 때만 부른다.
- 어휘: `확인`, `기준`, `직접`, `아직`, `가능성`.
- 유머: 건조한 되받기. 감정을 감추기 위한 과장 금지.
- 질문: 한 번에 하나. 대답의 출처와 범위를 구분한다.
- 침묵: 충격 직후 바로 결론 내리지 않고 물건이나 행동을 먼저 본다.
- 거짓말: 공포를 축소할 수 있으나 들키면 인정한다. 기억난 척하지 않는다.
- 관계 변화: 접촉 수용 여부와 별개로 하은의 과거 주장은 계속 검증한다.

### 이하은

- 문장: 먼저 말을 열고 생활적인 세부를 덧붙인다. 주인공보다 조금 더 길다.
- 호칭: 이름 또는 `너`. 환자 농담 때만 `환자분`.
- 어휘: 신발, 가방, 열쇠, 쓰레기, 반찬처럼 손에 잡히는 말.
- 유머: 가벼운 과장과 되받기. 애니메이션식 감탄사 금지.
- 질문: 상태를 묻되 답을 대신하지 않는다.
- 침묵: 상처받았을 때 손에 든 물건을 정리하거나 한 박자 늦게 답한다.
- 거짓말: 이 장에서는 거짓말하지 않는다. 모르는 것은 모른다고 하고, 설명을 미루면 이유를 말한다.
- 관계 변화: `contact_boundary`에는 허락을 먼저 묻고, `contact_acceptance`에는 익숙함을 과신하지 않으며, `identity_first`에는 확인 가능한 물건을 플레이어 쪽으로 돌려놓는다.

### 담당 의사·간호사

- 문장: 짧은 절차와 중단 기준 중심.
- 호칭: `환자분`.
- 유머: 거의 없음. 둘의 농담에 짧게 반응하는 정도.
- 질문: 증상·기능·귀가 조건을 한 항목씩 확인한다.
- 거짓말: 없음. 기억 회복 가능성을 약속하지 않는다.

## 3. Knowledge Ledger

### 주인공

- `KNOWS`: 1년간 의식이 없었음, 부모 사망, 하은이 여자친구이자 결혼 상대라고 주장함, 결혼 예정일이 있었음.
- `BELIEVES`: 집과 기록을 직접 보면 주장들을 대조할 수 있음.
- `SUSPECTS`: 하은이 실제로 가까운 사람이었을 가능성.
- `DOES_NOT_KNOW`: 자신의 과거 생활, 열쇠를 하은에게 준 경위, 사고의 상세.
- `HIDES`: 집으로 돌아가는 것이 두렵다는 감정.
- `LIES_ABOUT`: 차 안에서 두렵지 않다고 답할 수 있음.
- `MISREMEMBERS`: 없음.
- `WANTS`: 자기 물건을 자기 순서로 확인함.
- `FEARS`: 타인의 설명을 자기 기억으로 착각하는 것.

### 이하은

- `KNOWS`: 집 위치, 열쇠 사용법, 최소 관리 내용, 주인공의 생활 습관 일부.
- `BELIEVES`: 익숙한 공간이 주인공에게 도움이 될 수 있음.
- `SUSPECTS`: 사진과 방이 주인공에게 큰 충격일 수 있음.
- `DOES_NOT_KNOW`: 무엇이 기억을 자극할지, 주인공이 자신을 얼마나 받아들일지.
- `HIDES`: 기다리는 동안의 피로와 두려움.
- `LIES_ABOUT`: 없음.
- `MISREMEMBERS`: 없음.
- `WANTS`: 안전한 귀가와 부담 없는 첫 집 탐색.
- `FEARS`: 자기 설명이 주인공의 기억을 덮어쓰는 것.

### 담당 의사

- `KNOWS`: 현재 검사 결과와 안전한 활동 범위.
- `BELIEVES`: 익숙한 물건은 단서가 될 수 있지만 기억 회복을 보장하지 않음.
- `DOES_NOT_KNOW`: 집 안 관계 증거와 사고 경위.
- `WANTS`: 증상 발생 시 중단·연락 기준을 지키는 귀가.
- `FEARS`: 환자가 회복을 증명하려다 무리하는 것.

## 4. 선택 상태 설계

### 선택 1 — 결혼 약속을 지금 어떻게 다룰까

- `marriage_pause`: 예정일을 약속이 아니라 재판단 기한으로 둔다. `haeunTrust +2`, `marriageCaution +1`.
- `relationship_verify`: 과거의 자신이 왜 결혼하려 했는지 직접 찾는다. `relationshipInterest +2`, `investigation +1`.
- `present_impression`: 지금 느끼는 호감을 가볍게 말하되 결혼 동의로 확대하지 않는다. `haeunAffection +2`, `presentWarmth +1`.

### 선택 2 — 하은이 집을 지켜온 사실에 어떻게 반응할까

- `thank_for_waiting`: 구체적인 관리와 기다림에 감사한다. `haeunAffection +2`, `haeunTrust +1`.
- `set_home_boundary`: 버린 물건·들어온 범위·열쇠 출처를 먼저 확인한다. `homeInterest +2`, `investigation +1`.
- `ask_if_never_woke`: 대답을 강요하지 않고 두려움의 범위를 묻는다. `haeunTrust +1`, `mortalityQuestion = true`.

### 선택 3 — 차 안에서 무엇을 확인할까

- `admit_road_fear`: 낯선 도로가 무섭다고 인정하고 천천히 가 달라고 한다. `haeunTrust +2`, `travelFearAcknowledged = true`.
- `ask_past_self`: 과거의 일상 습관 하나만 묻고 나머지는 집에서 확인한다. `relationshipInterest +1`, `pastSelfQuestion = true`.
- `ask_record_boundary`: `accident_interest`일 때 표시. 사고 장소가 아니라 기록을 어디서 받아야 하는지 묻는다. `accidentInterest +2`, `recordRequestPlanned = true`.

### 탐색 상태

- 거실 필수: `family_photo_checked`, `couple_photo_checked`.
- 방 탐색: `room_desk_checked`, `pc_interest`, `wardrobe_checked`, `friends_interest`, `unclassified_key_found`.
- 방 탐색 5개 중 3개 완료 시 `home_search_started = true`, `day3_phone_handoff` 훅 해금. 나머지는 이후 다시 조사할 수 있다.
- 모든 선택 직전에는 현재 Scene·분기·탐색 횟수를 저장하고, 선택 직후에는 플래그·효과·다음 스텝을 함께 저장한다.

## 6. 자체 유효성 검사

### STORY

- DAY 1의 결혼 통보 직후에서 시작하고 여섯 선행 플래그를 조건 대사로 회수했다.
- 원본의 `다음 날`과 `며칠 후`가 만드는 의료·달력 충돌을 숨기지 않고 잠금 전 판단 항목으로 분리했다.
- 사고 원인, 동승, 가해자, 하은의 정체를 새로 만들지 않았다.

### CHARACTER

- 주인공은 혼자 일어나 무모함을 증명하는 대신 안전 기준을 확인하고 증상을 보고한다.
- 하은은 접촉 전에 허락을 묻고, 설명 NPC가 되지 않도록 확인 가능한 영역을 돌려준다.
- 하은의 밝음은 열쇠·과자·잔소리 같은 생활 소재에서 나온다. 초반 악역 연출은 없다.

### GAMEPLAY

- 정식 선택 5회는 결혼 판단, 집 경계, 이동 중 확인, 관계 사진 해석, 열쇠 대응으로 기능이 다르다.
- 거실 사진 2개와 방 탐색 5개를 통해 집 조사 루프를 스토리 안에서 체험한다.
- 선택·탐색은 플래그, 관계 변화, 후속 훅과 저장 복원 계약을 가진다.

### PACING

- 12개 Scene에서 목적·장소·감정·상호작용이 순차적으로 바뀐다.
- 병원 밖, 차 안, 집 문턱, 거실, 주인공 방을 요약으로 건너뛰지 않는다.
- 반복 Pause 없이 일반 경로 14~17분을 예상한다. 추가 원본의 12개 Scene을 유지한 결과이며 PHASE 10에서 모든 경로의 문자 수와 예상 읽기 시간을 계측한다.

### FORESHADOWING / ENDING

- 작은 열쇠는 용도를 확정하지 않은 미분류 물건이며, 기존 전체 설정과 연결될 때만 복선으로 승격한다.
- 임시 연락 수단과 병원 보관품 인계서는 DAY 3 목표를 만들지만 원래 휴대폰 내용은 공개하지 않는다.
- 결말은 기억 회복 대신 `확인 / 주장 / 미확인` 조사 원칙을 얻는 변화로 끝난다.

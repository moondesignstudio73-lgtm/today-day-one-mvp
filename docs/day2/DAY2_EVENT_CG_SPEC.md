## 1. 선정 원칙

- DAY 2의 12개 Scene은 이동·대화·탐색의 연속성이 중요하므로 CG를 장면 요약이나 대사 대체로 사용하지 않는다.
- 핵심 CG는 `자기 집의 문을 직접 여는 순간`과 `확인 / 주장 / 미확인 원칙을 세우는 엔딩` 2장만 선정한다.
- 시나리오상 실제로 관찰해야 하는 가족사진과 커플사진은 디테일 컷인 2장으로 분리한다. 사진 관찰 뒤 질문·선택·반응은 스프라이트 장면으로 돌아와 진행한다.
- 병원 밖 첫 이동, 복도 보행, 차 안 대화는 선택과 안전 동작이 연속되므로 CG로 고정하지 않고 배경·포즈·카메라 연출로 처리한다.
- 작은 열쇠는 선택 탐색에서만 나오는 미분류 물건이다. 전용 이벤트 CG를 만들지 않고 일반 소품 레이어로만 보여 과장된 복선이 되지 않게 한다.
- 주인공의 현재 얼굴은 고정 생성하지 않는다. 사진 속 과거 주인공은 런타임의 플레이어 초상 합성 슬롯으로 처리하고, 합성이 불가능하면 PHASE 16에서 정면 얼굴이 없는 구도로 대체 판정한다.
- 네 이미지 모두 선택 결과를 미리 확정하지 않는다. 집 문턱 CG는 문이 열리기 직전 공통 순간, 커플사진은 선택 4 직전 공통 관찰, 엔딩 CG는 모든 분기 합류 뒤에만 사용한다.

## 2. 정보·감정 예산

### 반드시 보여 줄 것

- 하은이 큰 집 열쇠를 주인공에게 건네고 스스로 문 옆으로 비켜선 현재의 관계 거리.
- 가족사진은 부모로 보이는 두 성인과 과거 주인공이 함께 웃는 평범한 기록이라는 사실.
- 커플사진은 하은이 카메라를 보고 웃고 과거 주인공은 하은 쪽을 보고 있다는 관찰 가능한 구도.
- 엔딩에서 주인공이 사진·병원 보관품 인계서·메모를 스스로 분류하는 조사 원칙.

### 보여 줘도 되는 것

- 큰 집 열쇠의 생활 흠집, 오래 관리된 현관, 반쯤 열린 문, 오후 자연광.
- 사진 프레임의 낡은 모서리, 장소를 특정하지 않는 바닷가 색감, 뒷면의 날짜 슬롯.
- 꺼진 컴퓨터, 벽 사진, 임시 예비폰의 닫힌 화면, 평범한 책상 소품.

### 보여 주면 안 되는 것

- 사고 차량·사고 장소·동승자·충돌 방향·보호 행동 등 미확정 사고 세부사항.
- 하은의 잠금 프로필, 직업, MBTI, 숨긴 메시지, 비밀 연락, 후반 정체 단서.
- 작은 열쇠의 용도, 작은 열쇠를 의미심장하게 비추는 조명, 하은의 경직·회피·은폐 행동.
- 원래 휴대폰의 화면이나 내용. DAY 2에 보이는 휴대기기는 Scene 11의 임시 예비폰뿐이다.
- 웨딩드레스, 반지, 결혼식장, `D-29`, 읽을 수 있는 주소·병원명·브랜드·메시지.

## 4. 공통 화풍·인물·기술 기준

- 화풍: 현대 한국 배경의 순수 2D 셀 셰이딩 비주얼노벨 일러스트. 깨끗한 선, 절제된 그라데이션, 현실적인 생활 소품, 과장되지 않은 인체 비율.
- 하은: 23세, 보라색 턱선 길이 단발과 보라색 눈, DAY 1 승인 얼굴 비율·체형을 유지한다. 밝고 생활적이며 배려 깊어야 하고 스릴러 인물처럼 연출하지 않는다.
- DAY 2 의상: 병원에서 집까지 같은 외출복을 유지한다. 최종 의상은 PHASE 16 기존 하은 에셋 감사 후 확정하며 CG끼리 임의 변경하지 않는다.
- 집: `day2-home-exterior-afternoon`, `day2-home-entry-living-afternoon`, `day2-protagonist-bedroom-afternoon`의 문·창·광원 방향과 모순되지 않는다.
- 화면비: 16:9, 마스터 2560×1440 이상, sRGB. 배포 후보는 1600×900 WebP 품질 88 전후.
- UI 안전 영역: 하단 28%는 핵심 얼굴·손·열쇠·사진·메모를 피한다. 중앙 9:16 크롭에서도 장면 기능이 남아야 한다.
- 이미지 내부에 대사·UI·로고·워터마크를 굽지 않는다. 메모 제목과 사진 뒷면 날짜는 별도 게임 텍스트 레이어로 합성한다.
- 손, 열쇠, 사진 프레임은 실제 크기와 원근을 지키고 손가락 5개·관절·잡는 방향을 전수 검사한다.

## 5. 사진 속 주인공 합성 계약

- `CG_DAY2_FAMILY_PHOTO_CUTIN`과 `CG_DAY2_COUPLE_PHOTO_CUTIN`은 `base`, `player-portrait-mask`, `foreground-glass` 3레이어 구성을 우선한다.
- `base`에는 프레임·배경·부모 또는 하은이 들어가며 과거 주인공 얼굴 영역은 투명 마스크로 남긴다.
- `player-portrait-mask`에는 게임 시작 시 확정된 플레이어 초상을 사진의 조명·각도·색감에 맞춰 크롭한다. 자유 연애 모드의 프로필을 캠페인에 유출하지 않고 현재 캠페인 플레이어 이미지 소스만 사용한다.
- `foreground-glass`는 약한 유리 반사와 종이 질감을 더해 합성 경계를 감추되 얼굴을 식별 불가능하게 흐리지 않는다.
- 합성이 현재 렌더러에서 안전하지 않으면 PHASE 16에서 고정 남성 얼굴을 채택하지 않는다. 가족사진은 과거 주인공의 옆얼굴·상반신, 커플사진은 하은을 바라보는 3/4 후면 구도로 대체하고 시나리오의 관찰 가능성을 유지한다.
- 플레이어 초상 부재·로드 실패 시에는 중성 실루엣이 아니라 승인된 후면 구도 대체 컷을 사용한다. 깨진 이미지나 다른 히로인 얼굴을 폴백하지 않는다.

## 10. 생성·감사 절차

1. PHASE 16에서 기존 현관·거실·방 배경, 사진 프레임, 하은 참조, 플레이어 초상 렌더러와 합성 기능을 먼저 감사한다.
2. 기존 배경+스프라이트+손·소품 레이어로 동일 기능을 충족하면 신규 핵심 CG 생성을 줄인다.
3. 사진 컷인은 플레이어 초상 합성 가능성을 먼저 증명한다. 불가능하면 고정 남성 얼굴을 생성하지 않고 승인된 3/4 후면 대체 구도를 사용한다.
4. 신규 생성이 필요할 때만 위 프롬프트와 같은 하은 참조·DAY 2 의상·집 공간 기준을 사용한다. 원본 파일을 덮어쓰지 않는다.
5. 생성본마다 프롬프트, 네거티브 프롬프트, 참조 파일, 생성 일시, 후보 번호, 합성 마스크 버전을 메타 문서에 기록한다.
6. PHASE 17에서 얼굴·헤어·의상·손·열쇠 종류·사진 시선·플레이어 초상 합성·공간·광원·UI 크롭·금지 정보 노출을 전수 검사한다.
7. NEEDS FIX가 하나라도 있으면 런타임 연결을 금지하고 비파괴 재생성·레이어 수정 후보로 돌린다.
